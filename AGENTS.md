# TraceLedger working agreement

- Work in this directory. Keep SecureFlow and university coursework unchanged.
- Before each small implementation milestone, explain its goal and tradeoffs, list exact files and commands, and obtain explicit approval. Do not combine future approvals.
- Obtain separate approval for dependency installation, Git initialization, each commit, remote creation, each push, and deployment. Confirm repository name and visibility before creating a remote.
- After an approved change, explain key code, show the diff or new-file contents and meaningful verification results, ask a brief understanding check, and wait. Let the user run and review commands when preferred.
- Build a Python investigation engine and Streamlit dashboard incrementally. Keep dependencies minimal. Azure, PowerShell, and ServiceNow are optional, separately approved extensions.
- Use deterministic synthetic logs or an explicitly authorized isolated lab. Do not use real credentials or personal logs. Do not scan public targets, exploit systems, lock accounts, isolate devices, or automate remediation.
- Label detections as rule-based lab findings, not proven compromise. Keep case notes and escalation recommendations explicitly simulated.
- Write original implementation. Identify starter-code provenance before using coursework as read-only conceptual reference; never copy or publish private course solutions.
- Keep private learning notes locally excluded. Inspect candidate public files and privacy exclusions before the first commit and push. Never commit secrets.
- Document only completed and verified features. Do not claim platform integrations or enterprise incident-response experience without evidence.
- Refresh familiar concepts and explain new ones without assuming proficiency from past Hack The Box experience.
